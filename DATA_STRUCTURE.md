# Data Structure - Single Source of Truth

This document defines the canonical data structure used across all outputs: on-screen results, email template, and PDF generation.

## Core Result Data Object

All outputs (UI, email, PDF) consume the same `resultData` object:

    traditionalScore: 29,        // 0-40 traditional component

    // Client information (for personalization)
    firstName: "John",
    lastName: "Doe",
    email: "john@example.com",
    advisorEmail: "advisor@petra.com",

    // All question answers (keyed by question name)
    answers: {
        // Traditional Risk Assessment

## Narrative Text Generation

All narrative sections are generated by functions in `script.js` and called by both the UI and PDF generator:

### 1. Overall Summary
**Function:** `generateOverallSummary(resultData)`
**Heading:** "What Your Score Reflects"
**Used in:**
- On-screen results (line 1160 in script.js)
- PDF generation (line 204 in pdf-generator.js)

**Returns:** String paragraph describing what the overall score means in practical terms.

### 2. Mindset Insight
**Function:** `generateMindsetInsight(resultData)`
**Heading:** "Behavioral Tendencies and Investment Mindset"
**Used in:**
- On-screen results
- PDF generation (line 222 in pdf-generator.js)

**Returns:** Multi-paragraph text describing behavioral tendencies with concrete scenarios.

### 3. Traditional Insight
**Function:** `generateTraditionalInsight(resultData)`
**Heading:** "Time Horizon and Risk Capacity"
**Used in:**
- On-screen results
- PDF generation (line 240 in pdf-generator.js)

**Returns:** Text describing time horizon, goals, and practical risk capacity.

### 4. Alignment Check
**Function:** `generateAlignmentCheck(resultData)`
**Heading:** "How These Elements Work Together"
**Used in:**
- On-screen results
- PDF generation (line 258 in pdf-generator.js)

**Returns:** Analysis of how behavioral and traditional components align or diverge.

### 5. Planning Relevance
**Function:** `generatePlanningRelevance(resultData)`
**Heading:** "How Petra Uses This Information"
**Used in:**
- On-screen results
- PDF generation (line 276 in pdf-generator.js)

**Returns:** Explanation of how Petra uses this assessment in planning process.

## Output Formats

### A) On-Screen Results (index.html + script.js)

**Display order:**
1. Risk Band label (prominent badge)
2. Numeric score (large but less prominent than band)
3. Score label: "Risk Alignment Score"
4. Progress bar
5. Component scores (Behavioral 0-60, Traditional 0-40)
6. **Narrative sections** (5 sections as described above)
7. Understanding the Scale explanation
8. Risk Profile Scale visualization
9. (Couples only) Couple Comparison

**Data flow:**
1. User completes assessment
2. `calculateRiskScore()` generates resultData
3. `displayResults(result)` renders to DOM
4. Each narrative section calls its generation function and populates HTML

### B) Email Template (email-template.html)

**Content:** Compact summary only (no narratives)

**Includes:**
- Petra logo (assets/petra-email-logo.svg)
- Personalized greeting: "Thank You, {{firstName}}"
- Confirmation message
- Results summary card:
  - Risk Band (colored badge using {{riskBandColor}})
  - Risk Alignment Score ({{finalScore}})
  - Component scores side-by-side ({{behavioralScore}}, {{traditionalScore}})
- 1 brief paragraph: "This assessment helps organize our conversation, not define you..."
- PDF attachment callout
- Signature from Petra team

**Template variables to replace:**
- `{{firstName}}`
- `{{riskBand}}`
- `{{riskBandColor}}` - hex color based on score
- `{{finalScore}}`
- `{{behavioralScore}}`
- `{{traditionalScore}}`

**Data flow:**
1. Backend receives resultData as JSON POST
2. Loads email-template.html
3. Replaces {{variables}} with actual data
4. Generates PDF (see below)
5. Sends email with PDF attachment via SMTP

### C) PDF Generation (pdf-generator.js)

**Content:** Complete results + Q&A appendix

**Structure:**
1. **Cover Page**
   - Petra logo/wordmark
   - Title: "Risk Alignment Assessment - Results"
   - Client name
   - Assessment date

2. **Results Summary Page**
   - Risk Band (large, colored)
   - Risk Alignment Score (48pt gold)
   - Component scores in boxes (Behavioral, Traditional)
   - Disclaimer box (light gold background)

3. **Narrative Sections** (exact mirror of on-screen)
   - What Your Score Reflects
   - Behavioral Tendencies and Investment Mindset
   - Time Horizon and Risk Capacity
   - How These Elements Work Together
   - How Petra Uses This Information

4. **Appendix: Your Responses**
   - Section 1: Investment Mindset
   - Section 2: Investment Knowledge
   - Section 3: Traditional Risk Assessment
   - For each question: number, full text, selected answer(s)

**Data flow:**
1. User clicks action that triggers PDF generation
2. `downloadCompletePDF()` in script.js prepares resultData
3. Calls `generateCompletePDF(resultData, clientName, isCouple)` in pdf-generator.js
4. PDF generator:
   - Calls narrative generation functions (same as UI uses)
   - Accesses `questions` array for Q&A section
   - Formats with jsPDF
5. Downloads as: `Petra_Risk_Assessment_[ClientName].pdf`

## Questions Array Structure

The `questions` object contains three sections:

```javascript
const questions = {
    traditional: [
        {
            name: "age",
            question: "What is your age?",
            type: "select",
            options: [
                { label: "Under 35", value: "under_35" },
                { label: "35-44", value: "35-44" },
                // ... etc
            ]
        },
        // ... more questions
    ],
    behavioral: [
        {
            name: "loss_reaction",
            question: "How do you typically react to investment losses?",
            type: "likert",
            options: [
                { label: "Very uncomfortable", value: 1 },
                { label: "Somewhat uncomfortable", value: 2 },
                // ... etc
            ]
        },
        // ... more questions
    ],
    knowledge: [
        {
            name: "knowledge_stocks",
            question: "Which of these statements about stocks are true?",
            type: "multiselect",
            options: [
                { label: "Diversification reduces risk", value: "diversification" },
                { label: "Blue chip stocks are risk-free", value: "blue_chip" },
                // ... etc
            ]
        },
        // ... more questions
    ]
};
```

**Question types:**
- `select` - Single choice dropdown/radio
- `multiselect` - Multiple checkboxes
- `likert` - Numeric scale (typically 1-5)
- `slider` - Continuous range input

## Maintaining Single Source of Truth

**Critical principle:** All three outputs (UI, email, PDF) must pull from the same data and functions.

### ✅ Correct Approach:
```javascript
// script.js - Define narrative generation functions
function generateOverallSummary(data) { ... }
function generateMindsetInsight(data) { ... }
// etc.

// UI - Call functions to display
document.getElementById('overallSummaryText').textContent = generateOverallSummary(resultData);

// PDF - Call same functions
const summaryText = generateOverallSummary(resultData);
doc.text(summaryText, x, y);
```

### ❌ Wrong Approach:
```javascript
// DON'T duplicate text generation logic
// DON'T hardcode different text in PDF vs UI
// DON'T maintain separate copies of narrative text
```

## Backend Integration Required

The email and PDF system requires a backend endpoint:

**Endpoint:** `POST /api/send-results`

**Request body:**
```javascript
{
    resultData: { /* full resultData object */ },
    clientName: "John Doe",
    advisorEmail: "advisor@petra.com"
}
```

**Backend responsibilities:**
1. Receive resultData
2. Generate PDF using pdf-generator.js logic (or equivalent server-side)
3. Load email-template.html
4. Replace {{variables}} with actual data
5. Send email via SMTP with PDF attachment
6. Return success/failure status

**Example response:**
```javascript
{
    success: true,
    message: "Results sent to advisor@petra.com",
    pdfGenerated: true
}
```

## Testing Checklist

When making changes, verify single source of truth:

- [ ] UI displays narrative sections correctly
- [ ] PDF includes same narrative text (not hardcoded differently)
- [ ] Email template variables match resultData keys
- [ ] PDF Q&A section shows all questions with correct answers
- [ ] Risk band colors consistent across UI/email/PDF
- [ ] Score calculations identical everywhere
- [ ] No duplicated text generation logic
